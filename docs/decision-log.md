## 决策记录

### [D-001] 第一阶段范围限定

**日期**: 2026-08-29
**状态**: 已批准

**决策**:
- 仅支持龙口悦致酒店
- 仅支持区域运营总监视角
- 暂不支持 PMS/OTA 对接
- 暂不支持多集团架构

**理由**:
- 试点项目需控制范围
- 降低复杂度，聚焦核心价值
- 验证业务模型后再扩展

**影响**:
- 数据模型按单酒店设计，但预留多酒店扩展

### [D-002] Excel 作为数据来源和导出格式

**日期**: 2026-08-29
**状态**: 已批准

**决策**:
- Excel 是历史数据来源
- Excel 是最终导出格式
- 数据库设计基于业务实体，不是 Excel Sheet

**理由**:
- 慧友现有工作流基于 Excel
- 团队熟悉 Excel 操作
- 保持数据可追溯性

**影响**:
- 需要开发 Excel 导出模块
- 数据库结构与 Excel 格式解耦

---

### [D-003] 核算逻辑独立于 UI

**日期**: 2026-08-29
**状态**: 已批准

**决策**:
- 所有核算计算逻辑放在 `lib/accounting/` 目录
- 使用纯函数，无副作用
- 必须有单元测试覆盖

**理由**:
- 业务规则需要被测试
- 便于审计和追溯
- UI 变化不应影响计算逻辑

**影响**:
- 目录结构需包含 `tests/accounting/`
- 计算函数签名需保持稳定

### [D-005] GOP 计算公式

**日期**: 2026-08-31
**状态**: ✅ **已确认** - 来自慧友内部确认

**决策**:
```
GOP = 收入 - 总成本
总成本 = 变动成本 + 人工成本 + 提成成本 + 固定成本
```

**理由**:
- 慧友确认这是标准的 GOP 定义

**影响**:
- 核心核算引擎必须实现此公式
- GOP 计算是纯函数，必须有单元测试

---

### [D-006] 总部管理费独立于 GOP

**日期**: 2026-08-31
**状态**: ✅ **已确认** - 来自慧友内部确认

**决策**:
- 总部管理费提成**不计入 GOP**
- 必须作为**独立指标/独立成本项目**处理
- **不允许自行推导其与 GOP 的关系**

**理由**:
- 慧友明确：管理费与 GOP 无关

**影响**:
- 数据字典中 ManagementFee 是独立实体
- GOP 计算中不包含管理费
- 报表中管理费和 GOP 分别展示

### [D-008] 提交截止时间规则

**日期**: 2026-08-31
**状态**: ✅ **已确认** - 来自慧友内部确认

**决策**:
- 营业日数据必须在**次日 18:00 前**提交
- 截止时间必须基于 **business_date** 计算
- 不能使用 created_at + 24 hours

**公式**:
```
submission_deadline = business_date + 1 day + 18:00
```

**理由**:
- 慧友确认的流程要求

**影响**:
- 需要在系统中实现基于 business_date 的截止时间计算
- 需要提醒功能

### [D-010] 能耗字段设计

**日期**: 2026-08-31
**状态**: ✅ **已确认** - 来自慧友内部确认

**决策**:
- 必须区分：消耗量、单价、计算结果
- 示例：
  - electricity_consumption（消耗量）
  - electricity_unit_price（单价，店长维护）
  - electricity_cost（计算结果）

**计算公式**:
```
electricity_cost = electricity_consumption × electricity_unit_price
water_cost = water_consumption × water_unit_price
```

**理由**:
- 慧友确认：电费/水费单价由店长维护

**影响**:
- 能耗相关字段需要分离为消耗量、单价、成本三个字段
- 日核算输入/输出需要对应结构

### [D-011] 审核流程

**日期**: 2026-08-31
**状态**: ✅ **已确认** - 来自慧友内部确认

**决策**:
```
店长: DRAFT → SUBMITTED
总监: SUBMITTED → APPROVED
      SUBMITTED → REJECTED → DRAFT
```

**理由**:
- 慧友确认的标准审核流程

**影响**:
- 状态枚举: DRAFT, SUBMITTED, REJECTED, APPROVED
- 所有状态变化必须记录 audit log

### [D-012] 异常检测规则

**日期**: 2026-08-31
**状态**: ✅ **已确认** - 来自慧友内部确认

**决策**:
- 收入异常: `actual_revenue < expected_revenue × 0.95`
- 成本异常: `actual_cost > expected_cost`
- **第一版使用确定性规则，不使用 AI**

**理由**:
- 慧友确认的异常定义

**影响**:
- 异常检测是纯函数，需单元测试
- 不引入机器学习/AI 组件
